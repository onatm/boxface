# Gate A: Guest and Container Runtime

**Date:** 2026-10-06

**Result:** Pass

**Plan:** [Baseline Experiment](../plans/2026-10-baseline-experiment.md#gate-a-guest-and-container-runtime)

**Scripts:** `experiments/gate-a/`

---

## Summary

One manually launched Firecracker guest booted a read-only mkosi Debian baseline with a separate writable data disk, ran rootless Docker Compose with Postgres as an unprivileged user, and preserved data across a clean stop and start. All 19 boundary checks passed: no sudo, no rootful Docker socket, no writable system overlay, and no host Docker socket or host filesystem shares.

The host was a nested-virtualization DigitalOcean droplet. Results establish feasibility; timings and memory describe a nested guest and must be repeated on the ThinkCentre before they inform targets.

## Findings

1. **Firecracker's guest config omits the i8042 keyboard controller.** Without `SERIO_I8042` and `KEYBOARD_ATKBD`, `SendCtrlAltDel` is accepted by the API but ignored by the guest, so the host cannot request a clean shutdown. Firecracker keeps these options in a separate `ci.config`. Added to `kernel.fragment`; clean stop then completed.
2. **Firecracker's guest config omits `NF_TABLES_IPV6`.** `NFT_FIB_IPV6` and Debian's `ip6tables` (nft backend) depend on it. Added to `kernel.fragment`.
3. **Non-interactive SSH commands do not read `/etc/profile.d`.** `DOCKER_HOST` set there was missing for commands such as `ssh dev@guest docker info`, which is how agents and tools invoke commands. Setting it in `/etc/environment` (read by `pam_env`) fixed it.
4. **`docker-buildx-plugin` was not installed.** `docker build` fell back to the classic builder without BuildKit. Added to the image package list after the run; not yet re-verified.
5. **Docker 29 reports the storage driver as `overlayfs`.** This is the containerd image store's overlayfs snapshotter on the ext4 data disk, working unprivileged on the 6.18 kernel. No fuse-overlayfs was needed.
6. **Rootless network driver is slirp4netns**, selected by default because the package is installed.
7. **Read-only root needed these writable paths**, all declared in the image:
   - tmpfs `/var/log`, `/var/tmp`, `/var/lib/systemd`; journald `Storage=volatile`.
   - Linger for `dev` recreated at boot by `tmpfiles.d` under the `/var/lib/systemd` tmpfs.
   - SSH host key generated on first boot under `/var/lib/boxface/ssh` on the data disk.
   - Machine ID transient per boot.
8. **Setuid binaries present in the baseline:** `chfn`, `chsh`, `gpasswd`, `mount`, `newgidmap`, `newuidmap`, `passwd`, `su`, `umount`, `dbus-daemon-launch-helper`, `ssh-keysign`. Only `newuidmap` and `newgidmap` are required for rootless Docker; the rest come from Debian defaults.

## Decisions

- **Hypervisor:** Firecracker, provisional until confirmed on the ThinkCentre without nested virtualization. Cloud Hypervisor was not needed.
- **Docker execution:** Rootless daemon using system-installed Docker CE binaries.
- **Guest kernel:** Linux 6.18 LTS built from Firecracker's guest config plus a Boxface fragment, with all features built in.
- **Root filesystem format:** ext4 mounted read-only. erofs was not evaluated.
- **Docker storage:** containerd overlayfs snapshotter on the ext4 data disk.

## Not Covered

- Bare-metal behaviour and performance on the ThinkCentre.
- Compile performance.
- Guest isolation from the host management plane; NAT gave the guest access to the host address.
- Persistent machine ID and the real guest integration service; a socat stub reported readiness.
- Firecracker jailer.
- BuildKit builds (finding 4).
