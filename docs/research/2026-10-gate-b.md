# Gate B: Prebuilt User Profile

**Date:** 2026-10-09

**Result:** Pass

**Scripts:** `experiments/gate-b/`

---

## Summary

A Home Manager profile built on the host ran on the read-only Debian guest from Gate A without Nix in the guest. Only Home Manager's `home-path` package environment was exported. Its closure was embedded at `/nix/store` in the read-only root image and exposed as `/opt/boxface/profile`. Home Manager's activation script was not run. Claude Code, Codex, OpenCode, Pi, mise, Node, Rust, gcc, and Git resolved from the profile in non-interactive and login SSH shells and started with no network. A project using mise's Node 22 did not break any agent launcher, which use the profile's packaged runtimes.

The first run found two compatibility failures, both fixed in the baseline image: mise-installed Node needed `libstdc++6`, and client locales forwarded over SSH produced `setlocale` warnings. All Gate A boundary checks still passed.

The host was the same nested-virtualization DigitalOcean droplet as Gate A. Timings describe a nested guest.

## Findings

1. **Home Manager activation is not needed and would need mutable machinery.** The activation script calls `nix-build`, sets a Nix profile with `nix-env`, installs packages with `nix profile install` or `nix-env -i`, registers GC roots, links generated files into the home directory, and runs `sd-switch`. `home-path` alone ran every declared tool. The only generated home files were `.cache/.keep`, `.local/state/.keep`, `.config/environment.d/10-home-manager.conf`, and `.config/systemd/user/tray.target`; none were needed.
2. **Home Manager's session variables are not applied.** `hm-session-vars.sh` is in `home-path` but not sourced. For this profile it set only `LOCALE_ARCHIVE_2_27`. A profile whose modules set session variables would need them exported into the baseline environment by the builder.
3. **Prebuilt runtimes downloaded by mise link against the guest's system libraries.** Node from nodejs.org failed with `libstdc++.so.6: cannot open shared object file` until `libstdc++6` was added to the baseline image. Nix-built tools are unaffected. The baseline must carry the libraries common upstream binaries expect; Node and the agents are the only ones validated so far.
4. **Client locales break both glibc stacks.** macOS forwards `LC_ALL=en_GB.UTF-8` over SSH, and Debian's default `sshd_config` accepts `LANG` and `LC_*`. Debian's bash warned because the image has no locales, and Nix tools launched through shell wrappers (`pi`, `rustc`, `cargo`, `cc`) warned because Nix's glibc needs `LOCALE_ARCHIVE`. Decision: the guest ignores client locale variables and sets `LANG=C.UTF-8` in `/etc/environment`. Both glibc builds include C.UTF-8, so no locale data is required. Setting `LOCALE_ARCHIVE` fixed the Nix tools alone but not Debian's bash.
5. **PATH needs two entries.** `/etc/environment` (read by `pam_env`) covers non-interactive SSH commands, as in Gate A finding 3. Debian's `/etc/profile` resets PATH for login shells, so `/etc/profile.d/boxface-profile.sh` prepends the profile again.
6. **The Rust toolchain is about half the closure.** `rustc`, `rustc-bootstrap`, and LLVM total about 2.1 GiB. `rustc-bootstrap` is a build-time compiler retained by a runtime reference; the referrer has not been traced with `nix why-depends`. `glibc-locales` (222 MiB) is referenced by `hm-session-vars.sh` and is unused with C.UTF-8.
7. **The closure carries undeclared packages.** It includes `man-db` and Home Manager's configuration manpage, Perl and its modules (a Git dependency), Python 3, `direnv`, `ripgrep`, `fd`, and `bubblewrap`; their referrers, and whether Home Manager links any of them into `home-path`, have not been checked.
8. **mise skips signature verification without `gpg`.** The Node tarball checksum was verified; the GPG signature was not.
9. **Rust needs a C linker in the profile.** `rustc` links with `cc`, so the profile declares `gcc`; the baseline has no system compiler.
10. **No private keys were found** by the Gate A image scan, which now also covers the embedded store.

## Decisions

- **User package compiler:** Nix and Home Manager on the builder, using only `home-path`. Home Manager activation never runs, and the guest has no Nix.
- **Profile exposure:** The `home-path` closure is embedded in the read-only root image at `/nix/store`, with `/opt/boxface/profile` as a root-owned link, first on PATH through `/etc/environment` and `/etc/profile.d`.
- **Guest locale:** `LANG=C.UTF-8`; the SSH server does not accept client `LANG` or `LC_*`.
- **Baseline libraries:** The baseline carries `libstdc++6` for prebuilt runtimes installed by mise.

## Not Covered

- Agent authentication and agents doing real work (Gate C).
- Closure size reduction: tracing `rustc-bootstrap` and dropping `glibc-locales`, the Home Manager manual, and unneeded closure members.
- A separate read-only profile disk instead of embedding the closure in the root image.
- Home Manager session variables from modules other than `home.packages`.
- System libraries needed by prebuilt runtimes other than Node, and browsers.
- Builder isolation from the host.
- Bare-metal timing on the ThinkCentre.
